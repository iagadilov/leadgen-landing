# Launch checklist - AI LeadGen OS

## 1. Проверить template

- [ ] Открыть `../ai-leadgen-os-template`.
- [ ] Проверить, что есть `README.md`, `START_HERE.md`, `SETUP_GUIDE.md`, `STUDENT_ROADMAP.md`, `SAFETY.md`, `EXAMPLE_RUN.md`.
- [ ] Проверить `AGENTS.md` и `CLAUDE.md`.
- [ ] Проверить `docs/os/`, `memory/`, `commands/`, `data/schemas/`, `examples/`.
- [ ] Прогнать grep на реальные имена, телефоны, email, secrets, sessions, `leads.db`.
- [ ] Убедиться, что example run публично безопасен и использует вымышленные компании.
- [ ] Проверить, что `TEMPLATE_AUDIT.md` актуален.

## 2. Записать первые видео

- [ ] Видео 1: что это такое и почему это не SaaS.
- [ ] Видео 2: как работает первый run.
- [ ] Видео 3: как студент адаптирует workspace под себя.
- [ ] Короткое demo video 5-8 минут по `demo-video-script.md`.
- [ ] В каждом видео сказать: не обещаем клиентов на автомате, outreach только после approval.

## 3. Обновить лендинг

- [ ] Перенести структуру из `landing-copy.md`.
- [ ] Hero: главный CTA "Купить доступ к курсу".
- [ ] Второй CTA: "Оставить заявку на внедрение".
- [ ] Добавить блок "не SaaS / не один промпт / не кнопка клиентов".
- [ ] Добавить course offer.
- [ ] Добавить DFY offer как второй путь.
- [ ] Добавить proof/example run без реальных имён лидов.
- [ ] Добавить FAQ.
- [ ] Проверить mobile layout.

## 4. Подключить оплату или заявку

- [ ] Решить, где покупается курс: платёжная ссылка, Kaspi, Stripe, Telegram invoice, manual payment.
- [ ] Проверить thank-you flow после оплаты.
- [ ] Если оплаты пока нет - поставить CTA на заявку/лист ожидания.
- [ ] Не обещать доступ, если delivery ещё не готов.

## 5. Подготовить DFY form

- [ ] Поля: продукт/услуга, ниша, гео, лучший клиент, минимальный чек, прошлые каналы, good/bad examples, контакт.
- [ ] Отдельный вопрос: "хочу курс / хочу внедрение / хочу понять fit".
- [ ] Автоуведомление в рабочий канал.
- [ ] Сохранение заявки в leadgen-inbound без смешивания с другими воронками.

## 6. Написать старым лидам

- [ ] Использовать `old-leads-message.md`.
- [ ] Разделить: короткий WA/TG, подробный WA/TG, email, follow-up.
- [ ] Не писать тем, кто отказался / просил не писать.
- [ ] Дедуп перед отправкой.
- [ ] Логировать отправки.

## 7. Подготовить демо

- [ ] Открыть template repo в Claude Code / Codex.
- [ ] Подготовить экран с `START_HERE.md`.
- [ ] Подготовить экран с `docs/os/`.
- [ ] Подготовить экран с `commands/`.
- [ ] Подготовить экран с example run.
- [ ] Подготовить экран с Memory Patch.
- [ ] Подготовить экран с outreach drafts и `approval_required: yes`.

## 8. Проверить safety language

- [ ] Нет "клиенты на автомате".
- [ ] Нет "100% ЛПР".
- [ ] Нет "гарантированные продажи".
- [ ] Нет "полностью автономный робот".
- [ ] Есть human approval.
- [ ] Есть draft-only outreach.
- [ ] Есть честный блок ограничений.
- [ ] Есть объяснение, что плохой batch чинится через review + memory, а не масштабируется.

## 9. Перед запуском

- [ ] Финально прочитать landing copy вслух.
- [ ] Проверить, что курс продаётся как практическая сборка workspace, а не как набор промптов.
- [ ] Проверить, что template repo представлен как актив внутри курса.
- [ ] Проверить, что DFY не конкурирует с курсом, а является вторым путём.
- [ ] Проверить CTA и формы.
- [ ] Сделать тестовую заявку.
- [ ] Сделать тестовую оплату или ручной payment flow.
- [ ] Подготовить первый пост / story / рассылку.
