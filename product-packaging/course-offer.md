# Course offer - AI LeadGen OS

## Название

AI LeadGen OS

## Подзаголовок

Видеокурс + готовый setup для Claude Code / Codex, где ты собираешь свою систему поиска B2B-клиентов под нишу.

## Для кого

Курс для людей, которым нужен управляемый B2B-лидген, а не очередная база контактов:

- владельцы B2B-бизнесов;
- фаундеры и solo-builders;
- агентства и специалисты с понятным оффером;
- команды, которые хотят внедрить AI-агента в процесс поиска и квалификации лидов;
- люди, готовые ревьюить качество и учить систему на своих решениях.

## Что внутри

- Видеоуроки по сборке AI LeadGen workspace.
- Clean template repo.
- Setup для Claude Code / Codex.
- AGENTS.md и CLAUDE.md - операционный контракт агента.
- `docs/os/` шаблоны: company, offer, ICP, negative ICP, sources, outreach rules, success criteria, compliance.
- `commands/` playbooks: onboard, define ICP, find leads, enrich, score, review, learn from feedback, generate outreach, prepare campaign, watch inbox.
- `memory/` - правила, good/bad examples, tone, reply playbook, run notes.
- Memory Patch Protocol.
- Lead schema.
- Example run.
- Safety rules.
- Roadmap первых 4 недель.

## Результат

После прохождения курса у тебя должен быть рабочий AI LeadGen workspace под свою нишу:

1. описан бизнес и оффер;
2. сформирован ICP и negative ICP;
3. запущен первый small batch;
4. лиды проверены по evidence;
5. проведён review good / maybe / bad;
6. фидбек превращён в Memory Patch;
7. подготовлены outreach drafts с human approval.

## Формат

- Видеокурс.
- Практическая работа в template repo.
- Пошаговый roadmap.
- Example run как ориентир.
- Опциональный support/review в старших пакетах.

## Ограничения

- Курс не гарантирует продажи.
- Курс не гарантирует, что в любой нише найдутся качественные лиды.
- Курс не заменяет оффер и человеческие решения.
- Outreach не должен уходить без human approval.
- Автоматизация не должна обходить лимиты площадок.

## Почему это не просто "промпты"

Промпт может помочь один раз. Workspace нужен, чтобы процесс повторялся.

В AI LeadGen OS есть:

- структура бизнес-контекста;
- правила качества лида;
- schema для данных;
- папки ранов;
- review loop;
- memory, куда попадают решения владельца;
- approval gates;
- safety language;
- playbooks для разных режимов работы.

Commands - это не продукт целиком. Это интерфейс к системе.

## Почему система учится на review + memory patches

Главное топливо системы - не парсер и не модель. Главное топливо - твои причины:

- почему этот лид good;
- почему этот maybe требует enrichment;
- почему этот bad не подходит;
- какой тон звучит нормально;
- какой источник даёт мусор;
- какой signal реально означает покупательскую боль.

Когда эти причины остаются в чате, они исчезают. Когда они попадают в `docs/os/` и `memory/`, следующий batch становится точнее.
